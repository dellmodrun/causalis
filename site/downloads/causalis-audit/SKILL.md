# CAUSALIS Audit

Evaluate only the mandate supplied by the user. Never infer a missing control from project descriptions, wallet activity, or marketing copy.

## Workflow

1. Parse the mandate as JSON. If it is invalid, report the parse error and stop.
2. Check it against `assets/mandate.schema.json`.
3. Apply every rule in `references/rules.md` deterministically.
4. Return each rule as `pass`, `fail`, or `not_provided`, with the exact input field that caused the result.
5. Separate structural results from external verification. A passing mandate means the document declares the controls; it does not prove deployed code enforces them.

When Python is available, prefer `python scripts/audit_mandate.py <mandate.json>` so the published checks and report format are applied consistently. The script performs no network requests. Use `examples/valid.mandate.json` only as a format example; its identifiers are placeholders and are not deployment evidence.

## Output

Include:

- mandate name and chain exactly as supplied;
- timestamp generated by the auditing environment;
- rule-by-rule results;
- missing required fields;
- a prominent verification boundary;
- no composite safety score and no financial recommendation.

Never request private keys, seed phrases, wallet signatures, or custody.
